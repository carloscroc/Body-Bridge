## Recommended normalization rules (for Phase 2)
- `libraryId` source: `normalizeToLibraryId(title)` (existing helper) — lowercase, hyphenated, deduped to ASCII. Example: `normalizeToLibraryId("Ankle Dorsiflexion")` -> `ankle-dorsiflexion`.
- `sourceId` format: `notion:<notionPageId>` (stable string used for dedup in `createCanonicalExercise`).
- `sourceSystem`: `"notion"`
- `bodyRegion` map (Notion → Convex): Notion stores anatomical regions (Ankle, Arm, Foot, Forearm, Hand, Lower Body, Mandible, Neck, Pelvis, Scapula, Shoulder, Spine & Thorax, Toes, Upper Body, Wrist). The mission suggested categorical buckets (Chest/Back/Legs/Core/Full Body/Arms/Shoulders) but those buckets do not exist in Notion data — keep the anatomical value as-is unless the schema enforces an enum, then map minimally (e.g. Shoulder → Shoulders, Upper Body/Arm/Forearm/Hand/Wrist/Finger/Thumb → Arms, Lower Body/Pelvis → Legs, Neck/Mandible → Other, etc.). **Recommend keeping raw value to avoid silent data loss; user can re-map later.**
- `difficulty` map (Notion → Convex): Notion currently only has `Beginner` populated across all 51 video rows. Convex may accept `["Beginner","Intermediate","Advanced"]`; default to `Beginner` when missing.
- `category` default: `Strength` (Notion `⭐Movement Goal` and `⭐Movement Type` were null on all 51 video rows — recommend pulling these as separate fields and using `Strength` as the schema-level default).
- duplicate-key strategy: store `notionPageId` as `sourceId` on the canonical row; generate `libraryId` from the title. `createCanonicalExercise` must check both `(libraryId, sourceSystem)` AND `sourceId` before inserting (patch the helper). `assignExerciseToTrainer` is already idempotent via `by_trainer_exercise` index — reuse it.

## Blockers / open items (NOT blocking Phase 2, but flagging for user)
- **Seed-name mismatch.** The 6 names mentioned in the mission (Goblet Squat, Plank Hold, Walking Lunge, Bent-Over Row, Overhead Press, Romanian Deadlift) are not present in the Exercise Library data source under those exact titles. The 51 videos that DO have URLs are joint-by-joint mobility exercises (Ankle, Scapula, Shoulder, Wrist, Mandible, Neck, Thoracic, plus SMR lower-body). If the user expected those 6 names, the user either: (a) is looking at the wrong Notion source, (b) the exercises were renamed, or (c) those exercises exist in Notion but lack a video URL yet. Phase 2 can proceed with the 51 video-bearing pages as-is.
- **Duplicate video URL across two pages.** Both `Shoulder External Rotation` (`2fa97d6b-662f-8063-bf1b-facfd09bbcf5`) and `Shoulder Internal Rotation` (`2fa97d6b-662f-8043-ad3b-e32247e2f5b7`) reference `https://youtube.com/shorts/q6tOfr9_aDA?feature=share`. This is a data-quality issue in Notion — the user may want to fix it there. Both pages will still be inserted as separate canonical exercises (different `libraryId` and `sourceId`); only the trainerExercises `videoUrl` field will be identical.
- **Empty optional fields.** Across all 51 video rows, `equipment`, `musclesUsed`, `movementGoal`, `movementType`, `instructions`, `videoDescription`, `source`, `level`, `otherNames`, `status`, `clientGoal`, `location`, `visualsComplete`, `coverPhoto`, `dateAdded` are mostly null. Convex will need defaults or nullable handling for these — flag for the helper patch in Phase 2.
- **Property name correction.** The mission referenced `⭐Video` (no space). The actual Notion property name is `⭐Video Url` (with space and capital U). The inspect script was patched mid-run to use the correct name; document here so Phase 2 / future runs use the right key.
